# 0002. JGit은 테스트 오라클로만 쓴다

- 상태: 채택
- 날짜: 2026-11-23

## 맥락

Java에는 git 구현체인 JGit이 있다. 메인 코드에서 쓰면 빨리 동작하는 서버를 만들 수 있지만 이 프로젝트의 목적은 그 내부를 직접 구현하는 것이다.

## 결정

- 메인 코드(`src/main`)에는 JGit 의존성을 두지 않는다.
- 테스트에서는 결과 비교용 오라클로 쓸 수 있다. 1차 오라클은 실제 git CLI(`GitCli` 테스트 픽스처)다.
- JGit 소스는 같은 Java 구현이라 참고 자료로 읽는다. 코드를 옮긴 경우 EDL 라이선스 고지를 남긴다.
- git 본체(C, GPLv2) 코드는 옮기지 않는다. 공식 문서와 프로토콜 스펙을 보고 구현한다.

## 고려한 대안

- JGit을 메인 코드에서 쓰고 일부만 직접 구현: 학습 범위가 흐려지고, 어디까지 직접 만들었는지 설명하기 어렵다.
- 테스트에서도 JGit 금지: 검증 수단이 git CLI 하나뿐이라 프로세스 실행 비용이 큰 대량 비교 테스트가 느려진다.

## 결과

- 이력서와 면접에서 "어디까지 직접 구현했는가"가 명확하다.
- 교차 검증은 git CLI를 기본으로 하고, 대량 속성 테스트에서만 JGit을 고려한다.
