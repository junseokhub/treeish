# 0004. 해시 알고리즘을 처음부터 추상화한다

- 상태: 채택
- 날짜: 2026-11-23

## 맥락

git은 SHA-1에서 SHA-256으로 전환을 준비하고 있고, `git init --object-format=sha256`으로 SHA-256 저장소를 만들 수 있다. 객체 ID 길이(20바이트/32바이트)와 hex 길이(40/64)가 다르다.

## 결정

- `ObjectId`는 해시 알고리즘을 함께 가진다. 길이를 상수로 박지 않는다.
- 저장소를 열 때 `config`의 `extensions.objectformat`을 읽어 알고리즘을 정한다. 없으면 SHA-1이다.
- 테스트는 같은 시나리오를 SHA-1과 SHA-256 저장소 양쪽에서 돌린다.

## 고려한 대안

- SHA-1만 지원하고 나중에 확장: 20바이트 가정이 파서, 팩 인덱스, 프로토콜 곳곳에 퍼진 뒤에 고치는 비용이 크다.

## 결과

- 초기 구현이 조금 복잡해지지만, 팩 인덱스와 프로토콜(`object-format` capability) 단계에서 다시 고칠 일이 없다.
