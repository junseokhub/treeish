# 0001. 저장 포맷을 git 디스크 포맷과 같게 한다

- 상태: 채택
- 날짜: 2026-11-23

## 맥락

서버가 저장소를 어떤 형식으로 저장할지 정해야 한다. 학습 목적상 git 내부 구조를 그대로 다루는 것이 핵심이고, 구현이 맞는지 객관적으로 검증할 수단도 필요하다.

## 결정

베어 저장소 디렉터리 구조(`objects/`, `refs/`, `packed-refs`, `HEAD`, `config`)와 객체·팩 포맷을 git과 똑같이 쓴다.

## 고려한 대안

- 자체 포맷(예: 객체를 RDB나 KV 스토어에 저장)
  - 장점: 저장 계층을 자유롭게 설계할 수 있다.
  - 단점: git 도구로 검증할 수 없고, git 내부 구조를 배운다는 목적에서 벗어난다.

## 결과

- `git fsck`, `git cat-file`, `git log`로 treeish가 쓴 결과를 바로 검증할 수 있다.
- git이 만든 저장소를 테스트 픽스처로 그대로 쓸 수 있다.
- 저장 계층 분리(9단계)는 포맷이 아니라 접근 경로(gRPC 서비스)를 바꾸는 방식으로 한다.
